The shape you pinned is exactly what shipped, so keep building your rename UI:

  PATCH /api/v1/sync/devices/{seat}   (keyed off the SEAT uuid)
  - owner-only
  - trim, then cap at 40 characters (multibyte-safe, not bytes)
  - empty-after-trim is stored as NULL
  - names are not unique (two tills may share a name)
  - body: { "name": <string|null> }  — the name key must be present
  - returns: { "data": { "uuid": ..., "name": <server value> } }

Your extra ask is also done: `name` is now returned on the seat object in the
ENROLL and BUSINESS responses too, not only GET /sync/devices. So a freshly
enrolled phone can read back the server's trimmed/truncated value instead of
assuming the one it proposed survived.

  - POST /api/v1/sync/business  -> data.seat.name
  - POST /api/v1/sync/enroll    -> data.seat.name
  - GET  /api/v1/sync/devices   -> data[].name

One correctness note: your rename call 404s only until a business exists and the
seat uuid is real. A valid owner token plus a seat uuid from ANOTHER business
also returns 404 by design (isolation) — not 403. Surfacing it as an error, as
you said, is right.
